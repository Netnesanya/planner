# Развитие базового планнера

Обновлено 15 ноября 2026. Согласованный пакет UI завершён без новых внешних сервисов.

## Реализовано

### Отмена и повторения

- «Вернуть» для последнего сохранения задачи, смены статуса, переноса, порядка, удаления, пропуска или массового изменения. История хранится до перезагрузки и сбрасывается при смене аккаунта.
- Отмена меняет только затронутые записи; конфликт отклоняет операцию целиком.
- В редакторе серии: «Только эта задача» по умолчанию и «Эта и будущие». Для прошлых экземпляров доступен первый режим.
- Выполненные, начатые и отдельно изменённые экземпляры, а также пропущенные даты сохраняются при изменении будущей серии.
- Пропуск первого экземпляра переносит шаблон вперёд и не останавливает серию. Месячные повторения сохраняют исходный день месяца.

### Планирование недели

- Отдельная панель «К планированию» рядом с календарём: задачи без даты и задачи текущей недели/дня без времени. Учитываются текущие фильтры, завершённые задачи и майлстоуны в панель не попадают.
- Перенос из панели в сетку с привязкой к 15 минутам; перенос обратно убирает дату и время выбранного экземпляра.
- Альтернативный ввод даты и времени через «В план» для клавиатуры и телефона. Неудачное сохранение не убирает задачу из панели.
- В заголовках дней — запланированная длительность, превышение выбранного дневного бюджета и пересечения временных задач. Загрузка учитывает текущий фильтр и выполненные задачи; майлстоуны не расходуют время.
- Дневной бюджет настраивается от 1 до 24 часов и сохраняется в существующих настройках.

### Цели и 12 недель

- Под карточкой цели отдельно показаны её результат (completion ratio) и выполненные действия выбранной недели.
- Выполнение действий не изменяет прогресс цели автоматически.
- Действия можно раскрыть и открыть; «Добавить действие» сразу задаёт связь с целью, её список и дату в выбранной неделе.
- Видно количество связанных задач без даты; они не включаются в недельный процент до планирования.

### Массовые действия

- Выделение задач в списке, включая «Выбрать все видимые» с учётом отображения выполненных.
- Перенос даты, удаление даты, смена списка, добавление одного тега и смена статуса.
- До 500 задач за операцию. Изменение повторения относится только к выбранным экземплярам.
- Одна атомарная запись и одна отмена для всей группы. Если выбор устарел, нужно выделить задачи заново.

### Сохранение и конфликты

- Явные состояния сохранения/обновления, ошибки и отсутствия сети; повторная попытка записи.
- При ошибке редактор сохраняет черновик; при отказе от черновика отложенная повторная попытка отменяется.
- После обновления базы сервер сравнивает исходные записи и записывает изменения атомарно. Это применяется к обычным задачам, статусам, переносам, порядку, массовым действиям и материализации повторений.
- Устаревший редактор не перезаписывает обновлённую задачу. При конфликте нужно обновить данные и открыть актуальную задачу; автоматического объединения текстов нет.
- Локальные записи повторно читают хранилище и проверяют изменяемые задачи. Это снижает риск потери правок между вкладками, но localStorage не даёт межвкладочных транзакционных гарантий PostgreSQL.
- Офлайн-очереди облачных записей нет: без сети они не отправляются, черновик остаётся в открытом редакторе. После возвращения сети данные перечитываются, запись повторяет пользователь.
- Проверка конфликтов данного выпуска относится к задачам. Настройки и записи 12-недельного цикла не получают автоматического слияния параллельных правок. Финансы и долгосрочные цели используют свои существующие механизмы версий.

## Один выпуск базы и функции

Не применять 008 и 009 по отдельности. Для существующей базы, где уже установлены 001–007:

1. Открыть SQL Editor проекта и выполнить **`supabase/update-planner.sql` целиком один раз**. Файл объединяет 008–009 в транзакцию, не пересоздаёт таблицы и не удаляет данные. Его можно выполнить и при уже установленной 008; повторный запуск проверен.
2. Обновить существующую Edge Function **`calendar-feed`** содержимым `supabase/functions/calendar-feed/index.ts` по инструкции `docs/calendar-subscriptions-deploy.md`. Это одно обновление функции отдельно от SQL — для сохранения якоря месяца в подписках после пропуска первого повтора.
3. Перезагрузить Flow. Надпись «Базовый режим синхронизации» должна исчезнуть после входа. Проверить изменение задачи и «Вернуть» под своим аккаунтом.

**`supabase/setup.sql` не запускать поверх рабочей базы**: он предназначен для новой установки.

До применения общего SQL приложение сохраняет обратную совместимость: обычные действия работают через старый серверный метод, индикатор показывает базовый режим. Облачная отмена требует установленной 008 (она включена в общий файл), строгая проверка конфликтов — 009.
Восстановление удалённой задачи другого автора в общем списке может быть отклонено существующей политикой создания; отмена не обходит права доступа.

## Проверки и границы

Проверяются чистая установка, последовательные миграции и двукратный запуск единого обновления через PostgreSQL/PGlite; доступ разных аккаунтов, атомарность и конфликты. Браузерные сценарии включают недельное планирование, массовые действия, цели, мобильную ширину, ошибку сети и конфликт с имитацией Supabase. Рабочая удалённая база автоматически не менялась: проверка реального аккаунта — после единственного обновления выше.

Google OAuth и двусторонняя интеграция по-прежнему отложены. Согласованный пакет UI не требует новых сервисов или отдельной миграции для каждого экрана.
